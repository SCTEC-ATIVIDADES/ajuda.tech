Teste e ajustes da implementação LangGraph do assistente Herbert (Ajuda Tech). O agente usa OpenRouter API com modelos free para conversação e recomendação de computadores.

### Problemas encontrados e soluções

#### 1. Chain-of-Thought (CoT) exposto ao usuário

**Problema:** Modelos free do OpenRouter retornam raciocínio interno (thinking) antes da resposta final, visível ao usuário.

**Tentativas anteriores (não funcionaram):**
- Reforço de prompts com "IMPORTANTE: Retorne APENAS a mensagem final"
- Função `_strip_cot()` com regex para padrões de CoT em inglês
- Detecção de troca de idioma (CoT em inglês → resposta em português)

**Solução final:**
- Adicionado `"reasoning": {"effort": "none"}` no payload da API OpenRouter (`chat/services.py:157`)
- Função `_strip_cot()` em `chat/agent/nodes.py:46` como fallback (detecta parágrafos em português)

**Modelos testados:**
| Modelo | Resultado |
|---|---|
| `poolside/laguna-m.1:free` | Exibe CoT |
| `nvidia/nemotron-3-super-120b-a12b:free` | Exibe CoT |
| `nvidia/nemotron-3-nano-30b-a3b:free` | Exibe CoT |
| `tencent/hy3:free` | Exibe CoT |
| `openrouter/free` | Distribui entre modelos free |

**Conclusão:** Todos os modelos free expõem CoT no campo `content`. A solução é `reasoning.effort: "none"` na API.

---

#### 2. Frontend usando endpoint legado

**Problema:** `chatApi.js` apontava para `/send/` (endpoint legado) em vez de `/agent/send/` (LangGraph).

**Solução:**
- `chatApi.js`: `CHAT_ENDPOINT = '/agent/send/'`
- `chat.html`: Adicionado `?v=2` para cache bust

---

#### 3. LLM inventava produtos do catálogo

**Problema:** O LLM recomendava produtos que não existiam em `produtos.json` (ex: "Acer Aspire 3" quando o catálogo tem "Acer Aspire 5").

**Solução:**
- Prompt reforçado em `chat/prompts.py:138`: "REGRA ABSOLUTA: Use APENAS os produtos listados abaixo. NÃO invente"
- Fallback no `recommend()` em `chat/agent/nodes.py:227`: sem produtos, retorna mensagem direta sem chamar LLM

---

#### 4. Rate limit (429) consumindo requests

**Problema:** Free tier = 50 requests/dia. Cada mensagem gerava 3+ requests (1 original + retries no 429).

**Solução:**
- Removido retry no 429 em `chat/services.py:171` (retorna erro imediatamente)
- Reduzido `_DEFAULT_MAX_RATE_LIMIT_RETRIES` de 10 para 2

---

#### 5. Grafo LangGraph fazendo muitas chamadas LLM

**Problema:** Fluxo fazia 3-5 chamadas LLM por mensagem (classify → gather → extract → recommend → respond).

**Solução** (`chat/agent/graph.py`):
- Removido nó `extract_context` do fluxo
- `gather_needs` vai direto para `recommend` quando tem propósito + orçamento
- Máximo reduzido para **2 chamadas LLM por mensagem**

---

#### 6. Duplicação de mensagem no erro

**Problema:** Ao receber erro 429, a mensagem do usuário aparecia duplicada no chat.

**Causa:** `chatApp.js:85-89` fazia `appendMessage` (adicionava nova msg) além de marcar a existente como `failed`.

**Solução:** Removido `appendMessage` duplicado, mantendo apenas a marcação de status.
